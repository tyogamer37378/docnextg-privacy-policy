Privacy Architecture Summary

DocNextG is built around a private, on-device document processing model. All camera captures, document scanning, perspective correction, optical character recognition (OCR), and PDF file operations take place locally on your Android device. The application does not operate cloud document servers, and your documents, extracted text, and files are never uploaded to our servers.

100% On-Device Document Content

Your document images, OCR extracted text, generated PDFs, and local backups are stored exclusively in app-private storage on your device. Zero document bytes are uploaded.

Disclosed SDK Telemetry

Bundled Google ML Kit client dependencies transmit technical SDK performance metrics, API execution latency, error codes, and device metadata to Google infrastructure.

Planned Monetization Boundary

When advertising or Pro subscriptions are enabled in an app release, ad networks and billing frameworks operate under strict isolation and never receive your document content.

1. Introduction

This Privacy Policy explains how DocNextG (package name: com.polyforge.magicpage), developed and published by PolyForge, processes, handles, and protects information across Android devices.

DocNextG operates under a strict privacy-first standard: your sensitive contracts, receipts, identity documents, and personal files belong exclusively to you. We do not operate a remote document processing cloud or harvest personal files. This document outlines our on-device data handling practices, discloses the technical operational telemetry transmitted by bundled SDK client components, and describes the data handling associated with planned advertising and subscription features when enabled.

2. Information Handled by DocNextG

To deliver document scanning, text recognition, and file management, data handling is structured into distinct categories:

  • User Document Content (Processed & Stored 100% On-Device): Camera preview frames, captured document photos, gallery-imported images, perspective-cropped pages, extracted OCR text strings, generated PDF files, scanned QR/barcode payloads, Room SQLite database records (document titles, page counts, folder tags), and local backup archives (.mpbak).
  • SDK Operational Telemetry (Transmitted Off-Device to Google): Technical performance data, API execution latency measurements, error codes, device hardware specifications (model, manufacturer), Android OS build version, application version code (1), and an ephemeral installation identifier (instance_id) generated by bundled Google ML Kit client components.
  • Planned Monetization Data (Active Only When Enabled in App Release): Advertising identifiers (Google Advertising ID / GAID), coarse IP address, and interaction diagnostics processed by Google Mobile Ads (AdMob) in ad-supported releases, and anonymous purchase tokens verified through Google Play Billing in Pro subscription releases.

DocNextG does not require user accounts, email registration, passwords, or personal identity profiles to access document-scanning features.

3. Camera and Document Scanning

DocNextG requests runtime access to the device camera (android.permission.CAMERA) solely when you initiate document capture, ID card scanning, or QR code reading.

  • Camera preview frames are analyzed in real time directly on your device using native OpenCV and Android Jetpack CameraX libraries for automated edge detection, document boundary alignment, and perspective correction.
  • Live camera frames remain transiently in memory and are discarded immediately upon boundary calculation.
  • An image is only committed to storage when you explicitly tap the camera shutter or confirm an automated scan capture.
  • Camera captures and live viewfinder streams are never transmitted over the network.

4. Imported Photos and Documents

You may choose to import existing photographs from your device gallery into DocNextG to create or supplement multi-page documents.

  • DocNextG utilizes the modern Android system Photo Picker (ActivityResultContracts.PickMultipleVisualMedia). This system-managed dialog ensures that the application only accesses the specific images you explicitly pick.
  • DocNextG does not declare broad storage permissions such as READ_EXTERNAL_STORAGE or MANAGE_EXTERNAL_STORAGE. It has no access to your broader photo gallery or personal files.
  • Selected images are copied directly to the application's private internal storage directory (context.filesDir/images/). Imported photos are never uploaded or transmitted off your device.

5. Optical Character Recognition (OCR)

DocNextG provides on-device Optical Character Recognition (OCR) to recognize and extract text from scanned documents.

  • OCR is powered by Google ML Kit's on-device text recognition library (com.google.mlkit:text-recognition-chinese, supporting Latin, Chinese, Japanese, and Korean character sets).
  • All text recognition models execute locally on your device hardware (CPU/GPU) using models bundled inside the application package.
  • Your document images and the recognized text are processed entirely on your device and are never uploaded to external servers for text recognition.
  • Extracted text is saved locally in the application's private SQLite database (DocumentPageEntity.ocrText) where you can edit it, copy it to your clipboard, or export it.

6. PDF Creation and Local Storage

DocNextG provides a comprehensive suite of PDF tools, including document compilation, merging multiple PDFs, splitting pages, compression, and password protection.

  • All PDF rendering and compilation execute locally using on-device PDF processing libraries (PdfBox-Android and Android's native PdfDocument APIs).
  • Generated PDFs and document thumbnails are stored in the application's private sandboxed internal directory (context.filesDir and context.cacheDir).
  • DocNextG does not operate cloud document hosting, online synchronization, or remote document storage servers.

7. QR Code and Barcode Processing

DocNextG includes a QR code and barcode scanner powered by Google ML Kit's on-device barcode scanning library.

  • Barcode pattern recognition and decoding execute locally on your device's camera preview frames.
  • Decoded content is displayed on your screen. It is not saved to the database unless you explicitly save it as a document note.
  • If a scanned code contains an external web link, DocNextG sanitizes the URL through a strict scheme allowlist (allowing only http:// and https://). The link is only opened in your device's default external browser upon an explicit user tap.

8. Local Backup and Disaster Recovery

DocNextG provides an offline disaster-recovery backup tool allowing you to pack your document library and database records into an archive file (.mpbak / ZIP format).

  • Backup archive creation and extraction execute 100% locally on your device using standard compression libraries.
  • You control the destination of backup archives through Android's Storage Access Framework (SAF).
  • No Cloud Sync: Backups stay strictly on your device. DocNextG does not operate automated cloud backup. Moving an archive to another device or cloud drive requires explicit user action.

9. User-Initiated Sharing and Export

Your documents, images, and backup archives leave the application's private sandbox only when you explicitly trigger an export or share action.

  • When you share a document or PDF, DocNextG invokes the Android system Sharesheet via a secure FileProvider configuration.
  • FileProvider grants temporary, read-only content URI permissions strictly for the specific file you choose to share with the recipient application you select (such as an email client, cloud drive, or messenger).
  • Handling of exported files by third-party recipient applications is subject to those applications' respective privacy policies.

10. Advertising and Premium Subscriptions

DocNextG may offer advertising-supported free access and optional paid subscriptions. These features are only active when enabled in the applicable app release.

Free Tier Advertising (Google Mobile Ads / AdMob — When Enabled)

In releases where advertising is enabled:

  • The free version of DocNextG displays banner, interstitial, or native advertisements powered by Google Mobile Ads (AdMob).
  • Google AdMob may process device identifiers (such as the Google Advertising ID / GAID where permitted), coarse network IP address, and ad interaction diagnostics to serve ads, prevent fraud, and apply frequency caps.
  • Advertisements never receive your camera frames, scanned document images, OCR text strings, or PDF documents.

DocNextG Pro Subscriptions (Google Play Billing — When Enabled)

In releases where subscription features are enabled:

  • Users may optionally purchase a Pro subscription or lifetime license to remove all advertisements and access premium utility features.
  • Financial transactions, subscriptions, credit cards, and banking details are processed exclusively through Google Play's secure billing framework (Google Play Billing).
  • DocNextG never receives, stores, or processes credit card numbers, debit cards, bank details, or billing addresses.
  • DocNextG receives only anonymous purchase tokens and subscription entitlement status required to unlock Pro functionality on your device.

11. Strict Document Privacy Boundary

DocNextG maintains an absolute architectural boundary between user document content and third-party monetization or SDK services:

  • Google Mobile Ads (AdMob) does not receive document images, OCR text, generated PDFs, or QR/barcode payloads.
  • Google Play Billing does not receive document images, OCR text, PDFs, or QR payloads through the purchase flow.
  • Google ML Kit processes document images and OCR text strictly in-memory on the device silicon; document content is never transmitted to Google cloud infrastructure.

Document content remains isolated within the local device sandbox regardless of whether the user is on the free tier or the Pro tier.

12. SDK Diagnostics and Network Communications

The compiled DocNextG release package includes android.permission.INTERNET and android.permission.ACCESS_NETWORK_STATE:

  • Bundled ML Kit Diagnostics: Google ML Kit client dependencies include Google's DataTransport client (transport-backend-cct), which communicates with Google infrastructure (play.googleapis.com) to transmit operational telemetry (API duration, initialization states, error codes, device model, and anonymous installation IDs) to ensure SDK reliability.
  • Monetization Communications (When Enabled): In releases with active monetization, network access supports fetching advertisements (via Google AdMob) and verifying purchase receipts (via Google Play Services).
  • Zero Document Content Transmitted: Under no circumstances does any network communication transmit camera feeds, document images, OCR text strings, filenames, or user content. All core scanner utilities function completely without an active internet connection.

13. Data Storage and Security

We are committed to protecting your data through defensive engineering practices:

  • Operating System Isolation: All documents, images, and database entries are stored in sandboxed internal directories (context.filesDir), isolated from other applications by the Android security framework.
  • Directory Traversal Guards: Backup extraction tools validate relative file paths during decompression to protect against directory traversal exploits (Zip Slip).
  • Decompression Safeguards: Archive extraction enforces hard size and byte limits to mitigate archive-based denial-of-service risks.
  • Encrypted Transmission: All third-party SDK communications (ML Kit diagnostics, and future ad serving/billing verification) utilize HTTPS / TLS encryption in transit.

14. Data Retention and Deletion

You retain complete control over your local data:

  • In-App Deletion: You can permanently delete individual pages, scans, or entire folders within the app at any time, immediately removing them from the filesystem and database.
  • Complete App Reset: Clearing storage through system settings (Settings > Apps > DocNextG > Storage > Clear Storage / Clear Data) or uninstalling the app permanently purges all documents, database records, and settings from the hardware.
  • Telemetry Data: DocNextG does not operate accounts or maintain an off-device database of operational telemetry. Retention and processing of operational telemetry and advertising data collected by third-party SDKs are governed by the applicable documentation and privacy policies of Google.
