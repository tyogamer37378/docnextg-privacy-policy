Privacy Architecture Summary

DocNextG is built around a private, on-device document processing model. All document scanning, camera frames, imported photos, optical character recognition (OCR), and PDF file operations take place locally on your Android device. The application does not upload your documents to any cloud servers. The only off-device network communication consists of operational diagnostics transmitted by bundled Google ML Kit client libraries to maintain SDK reliability.

100% On-Device Document Content

Your document images, OCR extracted text, generated PDFs, and local backups are stored exclusively in app-private storage on your device. Zero document bytes are uploaded.

Disclosed SDK Telemetry

Bundled Google ML Kit dependencies transmit technical SDK performance metrics, API execution latency, error codes, and device info to Google infrastructure.

No Accounts & No Ads

DocNextG requires no login or user account. It contains zero advertising SDKs (No AdMob), no advertising tracking IDs, and no payment or billing SDKs.

1. Introduction

This Privacy Policy explains how DocNextG (package name: com.polyforge.magicpage) processes, handles, and protects information when you use our mobile document scanning application on Android devices.

DocNextG is engineered with a strict on-device data processing philosophy. We believe that your sensitive documents, contracts, receipts, and personal files belong exclusively to you. We do not operate a cloud document processing infrastructure or remote storage servers for your files. This document details our data handling practices and openly discloses the technical operational telemetry transmitted by third-party SDK components bundled within the application.

2. Information Processed by DocNextG

To deliver document scanning, text recognition, and PDF utility features, DocNextG processes information in two separate categories:

  • User Document Content (Processed & Stored 100% On-Device): Camera preview frames, captured document photos, gallery-imported images, perspective-cropped pages, extracted OCR text strings, generated PDF files, scanned QR/barcode payloads, Room SQLite database records (document titles, page counts, folder tags), and local backup archives (.mpbak).
  • SDK Operational Telemetry (Transmitted Off-Device to Google): Technical performance data, API execution latency measurements, error codes, device hardware specifications (model, manufacturer), Android OS build version, application version code (1), and an ephemeral installation identifier (instance_id) generated by Google ML Kit client components.

DocNextG does not require, collect, or store personal identity profiles, usernames, passwords, phone numbers, email contact lists, or physical addresses. The application contains no login or user account system.

3. Camera and Document Scanning

DocNextG requests access to your device camera (android.permission.CAMERA) solely to capture document images and scan barcodes.

  • Camera preview frames are analyzed in real time directly on your device using native OpenCV and Android Jetpack CameraX libraries for automated edge detection, document boundary alignment, and perspective correction.
  • Live camera frames remain transiently in memory and are discarded immediately upon frame processing.
  • An image is only saved to storage when you explicitly trigger the camera shutter or confirm an automated scan capture.
  • Camera captures and live viewfinder streams are never transmitted over the network by DocNextG.

4. Imported Photos and Documents

You may choose to import existing photographs from your device storage into DocNextG to create or supplement documents.

  • DocNextG utilizes the modern Android system Photo Picker (ActivityResultContracts.PickMultipleVisualMedia). This system-managed dialog ensures that the application only accesses the specific images you explicitly select.
  • DocNextG does not declare broad storage permissions such as READ_EXTERNAL_STORAGE or MANAGE_EXTERNAL_STORAGE. It has no access to your broader photo gallery or personal files.
  • Selected images are read into memory and copied directly to the application's private internal storage directory (context.filesDir/images/). Imported photos are never uploaded or transmitted off your device.

5. Optical Character Recognition (OCR)

DocNextG provides on-device Optical Character Recognition (OCR) to recognize and extract text from scanned documents.

  • OCR is powered by Google ML Kit's on-device text recognition library (com.google.mlkit:text-recognition-chinese, supporting Latin, Chinese, Japanese, and Korean character sets).
  • All text recognition models execute locally on your device hardware (CPU/GPU) using models bundled inside the application package.
  • Your document images and the recognized text are processed entirely on your device and are never uploaded to external servers for text recognition.
  • Extracted text is saved locally in the application's private SQLite database (DocumentPageEntity.ocrText) where you can edit it, copy it to your clipboard, or export it.

6. PDF Creation and Local Storage

DocNextG provides a comprehensive suite of PDF tools, including document generation, merging multiple PDFs, splitting pages, compression, and password protection.

  • All PDF rendering and compilation execute locally using on-device PDF processing libraries (PdfBox-Android and Android's native PdfDocument APIs).
  • Generated PDFs and document thumbnails are stored in the application's private sandboxed internal directory (context.filesDir and context.cacheDir).
  • DocNextG does not provide or operate cloud document hosting, online synchronization, or remote document storage servers.

7. QR Code and Barcode Processing

DocNextG includes a QR code and barcode scanner powered by Google ML Kit's on-device barcode scanning library.

  • Barcode pattern recognition and decoding execute locally on your device's camera preview frames.
  • Decoded content (such as plain text or numbers) is displayed on your screen. It is not saved to the database unless you explicitly save it as a document note.
  • If a scanned code contains an external web link, DocNextG sanitizes the URL through a strict scheme whitelist (allowing only http:// and https://). The link is only opened in your device's default external browser if you explicitly tap to open it. DocNextG does not embed a web browser or track web browsing activity.

8. Local Backup and Restore

DocNextG provides a local disaster-recovery backup tool allowing you to pack your document library and database records into an archive file (.mpbak / ZIP format).

  • Backup archive creation and extraction execute 100% locally on your device using standard compression libraries.
  • You control the destination of backup archives through Android's Storage Access Framework (SAF).
  • No Cloud Sync: Backups stay strictly on your device. DocNextG does not operate automated cloud backup or Google Drive synchronization. To move an archive to another device or cloud drive, you must manually export or share the file yourself.

9. User-Initiated Sharing and Export

Your documents, images, and backup archives leave the application's private sandbox only when you explicitly trigger an export or share action.

  • When you share a document or PDF, DocNextG invokes the Android system Sharesheet via a secure FileProvider configuration.
  • FileProvider grants temporary, read-only content URI permissions strictly for the specific file you choose to share with the recipient application you select (such as an email app, cloud drive app, or messenger).
  • DocNextG has no control over how third-party recipient apps handle data after you transfer files to them.

10. Google ML Kit SDK Diagnostics & Telemetry

DocNextG integrates Google ML Kit client libraries to perform on-device text recognition and barcode scanning. These bundled libraries include Google's DataTransport subsystem (transport-backend-cct), which transmits technical operational telemetry to Google infrastructure (play.googleapis.com).

What Is Transmitted

Independent bytecode analysis confirms that the data sent by the ML Kit telemetry transport is limited to technical diagnostic and operational metrics:

  • Diagnostic & Performance Metrics: Invocation counts, API execution duration (minimum, median, maximum latency), model load status, and technical error/status codes.
  • Device & Application Metadata: Device hardware model, manufacturer, Android operating system build version, application version code (1), network connection type (Wi-Fi/cellular), and an anonymous per-installation UUID (instance_id).

What Is NOT Transmitted

Under no circumstances does this telemetry channel transmit document content. Independent audits of the application bytecode and network requests establish that:

  • Zero document images or camera pixels are transmitted.
  • Zero extracted OCR text strings are transmitted.
  • Zero document filenames, titles, or tags are transmitted.
  • Zero QR code or barcode payload values are transmitted.
  • Zero user account credentials or personal contact details are transmitted.

All telemetry data is transmitted using industry-standard encrypted network connections (HTTPS / TLS). Google processes this operational telemetry under standard Google API terms to monitor SDK performance, detect crashes, and maintain Google Play services reliability across Android devices.

11. Network Communications

The compiled DocNextG release package includes android.permission.INTERNET and android.permission.ACCESS_NETWORK_STATE in its merged manifest, introduced by the bundled Google ML Kit client dependencies.

  • Network socket communications are used solely for the transmission of the third-party ML Kit SDK diagnostic telemetry disclosed in Section 10.
  • DocNextG does not make network calls for document synchronization, user tracking, advertising, analytics profiling, or cloud computation.
  • All core document features—including camera capture, edge cropping, OCR text recognition, PDF generation, PDF merging, and local backup—function completely without an active internet connection.

12. Data Storage

All user document data, images, thumbnails, extracted text, and application settings are stored strictly in the private, sandboxed internal storage allocated to DocNextG by the Android operating system (context.filesDir and context.cacheDir).

Under Android's security architecture, sandboxed storage is isolated from other applications on the device. Other apps cannot read or access DocNextG files without your explicit user action through the system Sharesheet or Storage Access Framework.

13. Data Deletion

DocNextG provides users with complete, immediate control over local data:

  • In-App Deletion: You can permanently delete individual document pages, multi-page documents, or folders at any time directly within the application. When deleted, files are removed from the filesystem and database.
  • Application Data Clearing & Uninstall: Clearing application storage via Android system settings (Settings > Apps > DocNextG > Storage > Clear Storage / Clear Data) or uninstalling the app permanently purges all stored documents, images, database records, and settings from your device.
  • Telemetry Data: Operational SDK telemetry transmitted to Google is aggregated, technical, and not tied to user accounts. Because the application maintains no user profiles or identity mappings, DocNextG does not maintain an independent deletion portal for aggregated technical SDK telemetry logs held on Google infrastructure.

14. Security

We are committed to protecting your data through defensive engineering practices:

  • Path Traversal Guards: Backup archive extraction strictly validates relative file paths to prevent directory traversal vulnerabilities (Zip Slip).
  • Decompression Safeguards: Hard thresholds on archive size, entry counts, and decompressed bytes prevent Zip Bomb denial-of-service risks.
  • Scoped Content Sharing: File sharing is restricted strictly to designated export subdirectories via Android's FileProvider, preventing exposure of internal database records.
  • Safe URL Whitelisting: Scanned QR code payloads are validated to allow only standard http and https web links, blocking arbitrary intent or script execution.
  • Encrypted Transport: All SDK telemetry communications utilize HTTPS/TLS encryption in transit.
